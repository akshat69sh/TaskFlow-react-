Schema, validation and persistence
3. Let's understand with one practical TODO API
Imagine you want to create a TODO.

Step 1 — Model (models/todo.model.js)
The model defines how your data is stored in MongoDB.


import mongoose from "mongoose";

const todoSchema = new mongoose.Schema(
  {
    title: {
      type: String,
      required: true,
      trim: true
    },
    description: {
      type: String,
      default: ""
    },
    status: {
      type: String,
      enum: ["pending", "in_progress", "completed"],
      default: "pending"
    },
    user: {
      type: mongoose.Schema.Types.ObjectId,
      ref: "User",
      required: true
    }
  },
  {
    timestamps: true
  }
);

const Todo = mongoose.model("Todo", todoSchema);

export default Todo;

Step 2 — Service (services/todo.service.js)
The service contains the business logic. This is where you interact with the database.


import Todo from "../models/todo.model.js";

export const createTodoService = async (userId, data) => {
  const todo = await Todo.create({
    title: data.title,
    description: data.description,
    user: userId
  });

  return todo;
};

export const getTodosService = async (userId) => {
  return await Todo.find({ user: userId }).sort({
    createdAt: -1
  });
};

Step 3 — Controller (controllers/todo.controller.js)
The controller handles the HTTP request and response.


import {
  createTodoService,
  getTodosService
} from "../services/todo.service.js";

export const createTodo = async (req, res, next) => {
  try {
    const todo = await createTodoService(
      req.user.id,
      req.body
    );

    res.status(201).json({
      success: true,
      message: "Todo created successfully",
      data: todo
    });
  } catch (error) {
    next(error);
  }
};

export const getTodos = async (req, res, next) => {
  try {
    const todos = await getTodosService(req.user.id);

    res.status(200).json({
      success: true,
      data: todos
    });
  } catch (error) {
    next(error);
  }
};

Here, req.user.id is expected to be populated by your authentication middleware after verifying the user's JWT.

Step 4 — Routes (routes/todo.routes.js)
Routes define which controller should run when a particular API is called.


import { Router } from "express";
import {
  createTodo,
  getTodos
} from "../controllers/todo.controller.js";
import authMiddleware from "../middlewares/auth.middleware.js";

const router = Router();

router.post("/", authMiddleware, createTodo);
router.get("/", authMiddleware, getTodos);

export default router;

Register this route in app.js under /api/todos after implementing the authentication middleware.

The most important distinction is between Services and Utilities.

A service generally handles application-specific logic. For example, shareTodoService() verifies that the friend exists, checks sharing permissions, and creates a sharing record.

A utility is a reusable helper that doesn't own a business process. For example, a function that generates a JWT or formats a date.

For learning, I recommend following this rule:

Controllers stay thin, services handle business logic, models handle data, and utilities handle reusable helper functions.

That separation will make your TODO application easier to test, debug, and maintain as you add friends, sharing, task history, and notifications.
